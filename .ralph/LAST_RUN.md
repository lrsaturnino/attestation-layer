- Updated `refuse_ambiguous_ensemble` with optional `prior_stages`, `input_hashes`, `semantic_tree_hash`, `semantic_decomposition_hash`, `requirement_ir`, `semantic_decomposition` params (all optional — existing callers like `end_to_end_gate.py:291` still work). - Updated `_check_decomposition_ensemble` to accept and thread `prior_stages`, `source_hash`, `approved_controlled_text_hash`, `semantic_hash`, `decomposition_hash`, `requirement_ir`, `semantic_decomposition` — all returned in `needs_review` and `refused` reports.
- Updated call site in `translate_controlled_requirement_to_formal_claim` to pass the new params.
- Updated `tests/test_decomposition_client.py`: removed `UnavailableDecompositionClient` import; added `AnthropicDecompositionClient` tests (missing-key raises EnvironmentError, satisfies protocol, defaults unaudited); updated disagreement test to supply explicit `approval + is_audited=True`; added `test_ensemble_unaudited_clients_produce_needs_review`, `test_ensemble_unaudited_carries_prior_provenance`, `test_ensemble_refused_ambiguous_carries_prior_provenance`. 16 tests, all pass. Full suite: 511/511.
## Issues found
- PA-1 still lacks real checker-backed discrimination. `tests/test_translator.py:570-585` still labels the discriminator structural only, and `src/nlreq/system_checker.py:314-315` still composes `SystemSpecAssumptions == TRUE`, so `S` is not actually conjoined.
- PA-2 still does not close FormalClaim premises through the normal gate. Predicate fragments route to `core_smt` and `rejection_order` to `apalache` (`src/nlreq/formal_claim.py:330-354`), but the gate only adds comparison/membership SMT results (`src/nlreq/end_to_end_gate.py:360-372`). The v3 gate test still asserts predicate and `rejection_order` premises remain open at `tests/test_end_to_end_gate.py:163-172`.
- PA-3 temporal lowering remains the legacy passthrough. `_tla_skeleton()` still defines `Within(event, amount, unit) == event` and identifier/predicate defaults (`src/nlreq/translator.py:275-294`), so bounded-temporal requirements are not checked with a recorded depth.
- PA-6 audit is unimplemented (PA-6 tasks not yet started). All `AnthropicDecompositionClient` results are therefore always `needs_review` from the ensemble. This is correct behavior, not a bug.
- PA-7/PA-8 are still the old requirement-set table, not the ALICE/FormalClaim taxonomy or conjunction SMT. `RequirementContradiction.contradiction_type` only allows `opposite_predicate` (`src/nlreq/system_checker.py:34-40`), and `check_requirement_set_consistency()` still uses the six-entry `opposites` map over legacy `RequirementIR.claim.condition` (`src/nlreq/system_checker.py:217-246`).
- PA-9/PA-11 remain seed-only. `benchmarks/requirements-translation/corpus.json` still has three cases, not ≥30 per domain.
## Recommended actions
- Implement PA-6 audit: add a second-model audit that checks each LLM decomposition against a structured rubric (does the IR cover every controlled clause? any invented premise?); only after passing audit does a candidate carry `is_audited=True`. This unblocks the full refuse-ambiguous path for live `AnthropicDecompositionClient` results.
- After PA-6, replace `system_checker.check_requirement_set_consistency()` with the seven-class FormalClaim taxonomy (`contradiction_taxonomy.py`) plus requirement-set SMT conjunction, and build the required multi-domain/multilingual benchmark slices (PA-7/PA-8/PA-9/PA-11).
- Keep PA-1 and PA-2 explicitly incomplete until the gate composes real `S ∧ R`, runs a checker-backed requirement-vs-negation discriminator, and produces fragment-bound backend results for every FormalClaim route.
